# 极域电子教室 2017 运行逻辑解析

> 说明: 本文仅基于**静态分析**(文件清单、部署脚本、MSI 安装数据库字符串、官方原理 PDF)与公开资料整理, 全程未运行安装包中的任何可执行文件。文中标注了每条结论的来源。

## 1. 安装包静态观察 (来源: 本机目录分析)

```
极域2017标准版软件安装包/
├─ Student/Student_2.7.14459.exe      106MB  学生端安装器 (WiX/MSI 打包)
├─ Teacher/Teacher_2.7.14459.exe      173MB  教师端安装器
├─ Teacher/EduMythwareMonitor.exe     深信服VDI对接监控组件 (MFC, 读注册表 EduPort=9012)
├─ Teacher/PackTeacher.exe            深信服VDI打包工具

├─ VDEduH264Install.exe               H264 编解码组件
├─ vcredist_x86.exe                   VC++ 运行库
├─ 安装学生端.txt / 安装教师端.txt     部署脚本(管理员提权→防火墙端口→注册表→静默安装→重启)
└─ Docs/                              官方排障文档 (含《实现原理以及问题排查方法》)
```

部署脚本(`安装学生端.txt`)暴露的关键动作:
- 防火墙放行 TCP 9012/9013/9087 (VDAgentPort/ScreenOfficePort/ScreenBroadPort, 深信服VDI场景)
- 写注册表 `HKLM\SOFTWARE\TopDomain\e-Learning Class V6.0` 的 `BroadcastMode`
- 静默安装后 **自动重启系统** (`shutdown -r -t 5`)

MSI 安装数据库字符串(定点扫描 Student_2.7.14459.exe 得到)暴露的关键事实:

| 证据 | 含义 |
|---|---|
| `Manufacturer=Mythware`, WiX 打包 | 极域英文名 Mythware, 南京 TopDomain 出品 |
| 进程名 `StudentMain.exe` / `Student1.exe` / `DispcapHelper.exe` / `VRCwPlayer.exe` | 学生主进程 / 守护辅助 / 截屏辅助 / 网络影院播放器 |
| 注册表 `Software\TopDomain\e-Learning Class\Student` 下 `PreventKillEnable` | **防杀保护**开关(防止学生用任务管理器结束进程) |
| 同下 `UninstallPassword`、`LockScr...` | 卸载密码、锁屏相关配置 |
| `Software\TopDomain\eXchange\DesktopCaptureFPS`、`FrameQuality#100`、`FrameSpeed#3`、`GroupSize#32` | 抓屏帧率/画质/速度/分组大小等广播调优项 |
| 官方 PDF 截图: 教师/学生端均有"频道 ID"与"绑定IP"配置, 登录模式"选择教师/自动登录" | **频道隔离**机制: 教师端与学生端频道 ID 必须一致才能互通 |
| 官方 PDF 截图: 网络设置含"最大数据包大小 1440 字节"、"屏幕广播帧率 25fps"、"画面质量"、"LAN 10/100Mbps" | 广播按 MTU 分片, 带宽自适应 |

## 2. 总体架构 (来源: 官方《极域电子教育实现原理》PDF + 公开资料)

极域采用 **教师端-学生端 C/S 对等组网**, 同一局域网内:

```
            ┌─────────────────── 教师机 ───────────────────┐
            │  TeacherMain.exe                              │
            │  ├─ 发现/命令通道 (UDP, 含"频道ID"隔离)        │
            │  ├─ 数据通道 (TCP, 文件下发/上交等)            │
            │  └─ 屏幕广播流水线:                            │
            │      截图线程 ──> 编码线程×2 (JPEG/H264)       │
            │            ──> 发送线程 (拆 20KB/1440B 小片,   │
            │                    UDP 组播一发多收)          │
            └───────────────┬──────────────────────────────┘
                            │ 局域网 (同一网段, 组播可达)
        ┌───────────────────┼───────────────────┐
   学生机 StudentMain.exe   学生机 ...          学生机
   ├─ 接收命令(锁屏/消息/重启...)
   ├─ 加入组播组→解帧→解码→全屏渲染
   └─ 被监看/被演示时反向截屏上传
```

要点:
1. **发现与隔离**: 教师/学生配置同一"频道 ID"后才互通; 多网卡需手工绑定 IP; 登录模式可选"选择教师"(学生主动选教师机)或"自动登录"(按频道自动配对)。
2. **广播省带宽的核心设计是 UDP 组播**: 教师端编码后的画面**只发一份**到组播地址, 交换机负责复制给所有加入组播组的学生机。深信服 PDF 明确说明: 教室无论多少学生, 广播流量只有一份 (对比 TCP 单播 n 份, 60 台 × 4Mb/s ≈ 240Mb/s, 百兆交换机必崩)。
3. **三级流水线**: 截图线程写入截图缓冲区 → 两个编码线程轮流取帧编码(JPEG 整屏, 后续版本演进到 H264) → 发送线程取编码帧拆成约 20KB 的小片, 再按 MTU(1440B)打包发出。
4. **关闭广播用固定命令号**(PDF 中为 `0x0010`): 教师端 → EduShell → 学生端 → 学生退出组播组、恢复桌面。

## 3. 各功能的实现机制 (来源: 官方 PDF + 公开协议分析, 部分为通用做法推断)

| 功能 | 机制 |
|---|---|
| 学生上线/下线 | 学生端周期发送登录/心跳报文(带频道ID), 教师端超时未收到即判离线 |
| 屏幕广播 | 教师截屏→JPEG/H264编码→组播分片→学生端缓存整帧后解码渲染(乱序/丢片则丢帧) |
| 学生演示 | 选中学生的机器反向截屏→上传教师端→教师端再组播给其他学生 |
| 监看/远程控制 | 学生端截屏压缩上传到教师端缩略图墙; 远程控制时教师端把鼠标/键盘事件注入学生端 |
| 黑屏锁定 | 学生端创建全屏置顶无边框窗口, 配合键盘钩子屏蔽 Alt+Tab/Win 等快捷键 |
| 消息/通知 | 控制通道短报文 + 学生端弹窗 |
| 文件分发/上交 | TCP 数据通道, 大文件分块传输 |
| 网络影院 | 教师端媒体流+VRCwPlayer 播放 (需射手影音等解码器, 见安装说明) |
| 防退出 | `PreventKillEnable` 注册表项 + 进程守护(Student1.exe 辅助进程互拉) + 卸载密码 |
| VDI 场景 | 深信服改造版: 教师机 EduShell 不直接组播, 而是与学生虚拟机建立 TCP 长连接下发"打开广播"命令, 由学生 aDesk 上的 EasyConnect 进程加组播收流; 离线模式走 TCAgent (TCP 长连接), 见 PDF 时序图 |

## 4. 协议与安全特性 (来源: 公开协议分析, 供了解)

- 极域的命令报文是**二进制 TLV/定长结构**(带魔数、长度、命令号、频道号), 不是文本协议; 2016 起报文体采用**可逆的流式加密**(密钥从包头派生), 目的是防止学生用改包工具伪造命令, 并非真正密码学安全。
- 屏幕流按 RTP 风格分片(深信服 PDF 的排查命令中出现 `rtp_recv_time_out`、20492 字节数据包等字样), 丢片靠**整帧丢弃+下一帧全量刷新**恢复。
- 组播在跨网段/交换机开启 IGMP 检查时会失效——这正是官方排障文档中"广播黑屏/无反应"的最常见原因, 需要启用"组播代理"模式。

## 5. 对本项目 (ClassCtrl) 的映射

| 极域的做法 | ClassCtrl 的对应实现 |
|---|---|
| UDP 频道广播发现 | `Teacher.exe` 每 3 秒向 `255.255.255.255:15555` 广播 `TEACON` |
| 学生登录/心跳 | `Student.exe` 收到广播后发 `STULOGIN`, 之后每 2 秒 `STUHB` |
| TCP 数据/命令通道 | 每个学生与教师端一条 TCP 长连接 (`:15666`), 长度前缀帧 + ASCII 命令头 |
| 组播屏幕广播 + 拆片 | 截屏(降半分辨率 RGB555)→拆 1400B 片→UDP 组播 `239.10.10.10:15667`, 学生端重组整帧后渲染 |
| 全屏黑屏锁定 | 全屏置顶无边框窗口 + WH_KEYBOARD_LL 钩子屏蔽 Alt+Tab/Win/Alt+F4 |
| 文件下发 | 控制通道 `FILE|名|大小` 帧流式下发, 学生端存到 `文档\课堂接收文件` |
| 防退出/隐藏/自启 | **刻意不做**(透明运行、任务管理器可直接结束), 以符合课堂工具定位 |
